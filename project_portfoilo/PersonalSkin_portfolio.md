# פרק א' – ייזום {#פרק-א-–-ייזום}

## תיאור ראשוני של המערכת {#תיאור-ראשוני-של-המערכת}

**תקציר כולל ורציונל הפרויקט**

בעולם הטיפוח, אנשים רבים מתקשים להרכיב שגרת טיפוח פנים מתאימה לסוג העור שלהם, לגילם, לרגישויות ולתקציבם. מרבית הפתרונות הקיימים הם מאמרים כלליים או ייעוץ יקר אצל קוסמטיקאית. PersonalSkin היא אפליקציית ווב שמאפשרת למשתמשים למלא שאלון פרופיל עור מפורט ולקבל שגרת טיפוח בוקר וערב מותאמת אישית – שנוצרת באמצעות מודל שפה (OpenAI) כאשר מוגדר מפתח API, או לפי מנגנון גיבוי מבוסס כללים כאשר אין מפתח או כאשר הקריאה נכשלת. בנוסף, קיים דף קהילה בו משתמשים יכולים לשתף את הפרופיל והשגרה שלהם ולראות שיתופים של אחרים.

הממשק והתוכן מוצגים בעברית בכיוון RTL. ההמלצות מיועדות להסבר כללי בלבד ואינן תחליף לייעוץ רפואי או מקצועי.

**מה המוצר המוגמר אמור לבצע**

המוצר המוגמר אמור לאפשר לכל משתמש:
- להירשם ולהתחבר למערכת בצורה מאובטחת (סיסמאות מוצפנות, סשן אישי).
- למלא שאלון מקיף של פרופיל עור (סוג עור, גיל, חששות, רגישויות, מטרות, תקציב, זמן זמין, אקלים, הרגלי SPF, איפור, אקספוליאציה, ניסיון רטינול, הריון/הנקה ועוד).
- לקבל שגרת טיפוח בוקר וערב מותאמת אישית שנוצרת בזמן אמת ומוצגת כמסמך Markdown מעוצב.
- לעדכן את השאלון בכל עת ולקבל שגרה מחודשת (עם שמירת היסטוריית גרסאות).
- לשתף את הפרופיל והשגרה בדף קהילה עם שם תצוגה, ולצפות בשיתופים של משתמשים אחרים.
- לתת לייק/דיסלייק על שיתופים בקהילה.

**למה בחרתי את הפרויקט ואתגרים צפויים**

בחרתי את הפרויקט הזה מכיוון ששילוב בין פיתוח ווב מלא (צד שרת וצד לקוח) לבין שימוש בבינה מלאכותית הוא נושא שמאוד מעניין אותי ורלוונטי לעולם של היום. רציתי לבנות מערכת שרת-לקוח שלמה עם מסד נתונים, אימות משתמשים, אבטחת מידע, וחווית משתמש מלאה – ובנוסף לחבר אותה ליכולת AI שיוצרת תוכן מותאם אישית. האתגרים שצפיתי היו: עיצוב שאלון מפורט מספיק כדי שהמודל ייתן תוצאות טובות, כתיבת Prompt יעיל ל-OpenAI, הטמעת מנגנון Fallback שיתן שגרה סבירה גם ללא AI, ובניית ממשק משתמש בעברית RTL שנראה מקצועי ונוח.

## הגדרת הלקוח {#הגדרת-הלקוח}

**למי מיועדת המערכת ומי הולך להשתמש בה**

המערכת מיועדת לשני סוגי לקוחות עיקריים:

1. **אנשים שרוצים שגרת טיפוח אישית** – משתמשים שמתעניינים בטיפוח פנים אבל לא יודעים איפה להתחיל, או שרוצים המלצה מותאמת לסוג העור והצרכים הייחודיים שלהם ללא צורך בייעוץ יקר.
2. **קהילת טיפוח** – משתמשים שרוצים לראות מה אחרים עם פרופיל עור דומה משתמשים, לשתף את השגרה שלהם ולקבל השראה מאחרים.

## הגדרת יעדים/מטרות {#הגדרת-יעדיםמטרות}

**מה המטרות המרכזיות של המערכת המוצעת**

1. לספק שגרת טיפוח מותאמת אישית על סמך נתוני העור והצרכים של המשתמש.
2. לנצל בינה מלאכותית (OpenAI) ליצירת המלצות מפורטות ומותאמות, עם מנגנון גיבוי כללי שמבטיח שהמערכת תמיד תיתן תוצאה.
3. ליצור חוויית משתמש נקייה ומובנת בעברית.
4. לאפשר שיתוף ולמידה הדדית באמצעות דף קהילה.
5. להציג מערכת שרת-לקוח מלאה ומאובטחת (אימות, הצפנת סיסמאות, CSRF, XSS).

## בעיות, תועלות וחסכונות {#בעיות-תועלות-וחסכונות}

**מה הבעיות אותן אנו מנסים לפתור**

הבעיה הראשונה היא שמידע על טיפוח נגיש בעיקר בצורה כללית – מאמרים שמתייחסים לקטגוריה אחת ("עור שומני") בלי להתחשב בעשרות פרמטרים נוספים כמו אקלים, רגישויות, תקציב וזמן. הבעיה השנייה היא שייעוץ אישי (קוסמטיקאית/רופא עור) הוא יקר ולא תמיד נגיש. הבעיה השלישית היא שמשתמשים לא יודעים אם השגרה שלהם טובה – אין להם דרך פשוטה להשוות לאחרים עם פרופיל דומה.

**מה התועלות שסביר לצפות מהמערכת**

1. קבלת שגרת טיפוח מותאמת תוך שניות, ללא עלות.
2. התאמה לפרמטרים אישיים מפורטים (18 שדות בשאלון).
3. יכולת לעדכן ולהתאים את השגרה לאורך זמן (שמירת גרסאות).
4. למידה מהקהילה – צפייה בשגרות של אחרים עם פרופיל דומה.
5. חיסכון בזמן וכסף (אין צורך ביועץ).

**אילו שירותים המערכת תיתן**

הרשמה והתחברות מאובטחת, מילוי שאלון פרופיל עור מפורט, יצירת שגרת בוקר/ערב מותאמת אישית (AI או כללים), עדכון שאלון ויצירת שגרה מחודשת, צפייה בהיסטוריית גרסאות, שיתוף שגרה ופרופיל בדף קהילה, צפייה בשיתופים של אחרים, וכן לייק/דיסלייק על שיתופים.

**השוואת העבודה עם פתרונות ויישומים קיימים**

**SkinCare Routine by Dermstore** – מאמרים ומדריכים כלליים שמחולקים לפי סוג עור אך לא מותאמים לפרמטרים אישיים מפורטים. [קישור](https://www.dermstore.com)

**Curology / Proven Skincare** – שירותים בתשלום שמייצרים מוצרים מותאמים. הם דורשים מנוי חודשי ומשלוח פיזי, ולא רק שגרה טקסטואלית. [קישור ל-Curology](https://curology.com) [קישור ל-Proven](https://www.provenskincare.com)

**ChatGPT ישיר** – ניתן לשאול מודל שפה ישירות, אך הדבר דורש ניסוח Prompt מתאים ולא שומר היסטוריה, קהילה, או ממשק ייעודי.

PersonalSkin נבדלת מכל הפתרונות הללו בכך שהיא אפליקציה חינמית עצמאית, בעברית, עם שאלון מובנה, היסטוריית גרסאות, ודף קהילה – והכול בממשק אחד נוח.

## האם צפויים קשיים או מגבלות בהגדרת המערכת {#האם-צפויים-קשיים-או-מגבלות-בהגדרת-המערכת}

**האם מדובר בטכנולוגיה חדשה ובלתי מוכרת**

לא. כל הטכנולוגיות בהן נעשה שימוש הן מוכרות ומבוססות: Flask (Python), SQLAlchemy, HTML/CSS, ו-OpenAI API. החידוש הוא בשילוב ביניהן ליצירת מוצר שלם עם חוויית משתמש קוהרנטית.

**האם קיימים סייגים בהגדרת המערכת**

1. ההמלצות אינן תחליף לייעוץ רפואי – המערכת מציינת זאת בפני המשתמש.
2. איכות השגרה תלויה בזמינות ה-API של OpenAI – כאשר אין מפתח או שיש כשל, מופעל מנגנון Fallback פשוט יותר.
3. בתכנית חינמית של Render (שרת ייצור), השרת עלול "להירדם" לאחר חוסר פעילות.
4. מסד הנתונים ב-SQLite מתאים לפיתוח אך עבור סביבת ייצור עם הרבה משתמשים מקביליים מומלץ PostgreSQL.

## תיחום הפרויקט {#תיחום-הפרויקט}

**התחומים בהם הפרויקט עוסק**

הפרויקט עוסק בתחומים הבאים:

1. **מערכת שרת-לקוח** – שרת Flask (Python) שמטפל בבקשות HTTP מדפדפן (לקוח). תקשורת מבוססת HTTP/HTTPS.
2. **מסדי נתונים** – SQLite בפיתוח, PostgreSQL בייצור. שמירת משתמשים, פרופילי עור, שגרות, גרסאות, שיתופים ותגובות.
3. **אבטחת מידע** – הצפנת סיסמאות (Werkzeug hash), הגנת CSRF (Flask-WTF), מניעת XSS (Bleach), מדיניות סיסמה חזקה, תיעוד אירועי אבטחה (Audit Log).
4. **בינה מלאכותית** – שימוש ב-OpenAI Chat Completions API ליצירת תוכן מותאם לפי נתוני השאלון.
5. **מערכת הפעלה ותהליכים** – Thread ייעודי לכתיבת לוגים אסינכרונית (Queue + Worker Thread), פריסה על Linux (Render) ופיתוח על Windows.
6. **ממשק משתמש** – HTML/CSS בעברית RTL, עיצוב רספונסיבי, מסכים מרובים (בית, הרשמה, התחברות, שאלון, שגרה, קהילה).

**מה הפרויקט אינו כולל:**

- אין רכיב חומרה.
- אין יצירת מוצרים פיזיים.
- אין ייעוץ רפואי.
- אין תמיכה בשפות נוספות (עברית בלבד).

# פרק ב' – אפיון {#פרק-ב-–-אפיון}

## פירוט המערכת {#פירוט-המערכת}

בעולם של ימינו, ענף הטיפוח והקוסמטיקה גדל מדי שנה, ובמקביל גובר בלבול הצרכנים לגבי מה באמת מתאים ל��ם. המידע באינטרנט מוצף ולא תמיד אמין, ויש פער גדול בין מי שיכול לשלם ליועץ טיפוח אישי לבין מי שלא. PersonalSkin מגשרת על הפער: המשתמש ממלא שאלון מפורט של 18 שדות הנוגעים לסוג העור, הרגלים, אורח חיים ותקציב, והמערכת מייצרת עבורו שגרה אישית בפורמט ברור ומובנה. כאשר מוגדר מפתח API של OpenAI, השגרה נוצרת על ידי מודל שפה מתקדם (GPT-4o-mini); כאשר אין מפתח או שיש כשל, מופעל מנגנון גיבוי מבוסס כללים שמבטיח שהמשתמש תמיד יקבל תוצאה. בנוסף, דף הקהילה מאפשר שיתוף ולמידה הדדית.

## יכולות המערכת {#יכולות-המערכת}

1. הרשמה למערכת עם אימייל וסיסמה (כולל מדיניות סיסמה חזקה)
2. התחברות מאובטחת (סשן עם remember-me)
3. איפוס סיסמה (שכחתי סיסמה)
4. מילוי שאלון פרופיל עור מפורט (18 שדות)
5. יצירת שגרת בוקר מותאמת אישית
6. יצירת שגרת ערב מותאמת אישית
7. שימוש ב-AI (OpenAI) ליצירת שגרה חכמה
8. מנגנון Fallback – יצירת שגרה לפי כללים כאשר ה-AI לא זמין
9. שמירת היסטוריית גרסאות של שגרות
10. עדכון השאלון ויצירת שגרה מחודשת בכל עת
11. שיתוף פרופיל ושגרה בדף קהילה (עם שם תצוגה)
12. צפייה בפיד שיתופים של משתמשים אחרים (גם ללא התחברות)
13. לייק / דיסלייק על שיתופים בקהילה
14. תיעוד אירועי אבטחה אסינכרוני (Audit Log)
15. ממשק בעברית RTL נקי ונוח

## יכולות המערכת – פירוט פונקציונלי {#יכולות-המערכת-–-פירוט-פונקציונלי}

1. **הרשמה למערכת**

   **מהות היכולת**

   היכולת מאפשרת למשתמש חדש ליצור חשבון במערכת.

   **תהליכים ויכולות**

   * המשתמש ניגש לדף הרשמה וממלא: אימייל, שם פרטי (אופציונלי), שם משפחה (אופציונלי), סיסמה ואימות סיסמה.
   * הטופס עובר ולידציה: אימייל תקני, סיסמה עומדת במדיניות (8+ תווים, אות, מספר, תו מיוחד), אימייל לא רשום כבר.
   * הסיסמה מוצפנת (Hash) ונשמרת במסד הנתונים.
   * נוצר אובייקט User ונשמר ב-DB.
   * המשתמש מחובר אוטומטית ומופנה לשאלון.
   * אירוע `auth.register_success` נרשם ב-Audit Log.

   **אובייקטים בהם היכולת עושה שימוש**

   * User (מודל)
   * RegisterForm (טופס WTForms)

2. **התחברות למערכת**

# פרק ד' – עיצוב {#פרק-ד-–-עיצוב}

## תיאור הארכיטקטורה של המערכת המוצעת {#תיאור-הארכיטקטורה-של-המערכת-המוצעת}

המערכת בנויה בארכיטקטורת **שרת-לקוח** (Client-Server) קלאסית:

```
┌─────────────────────┐         HTTP/HTTPS         ┌──────────────────────────────┐
│   דפדפן (לקוח)      │  ◄──────────────────────►  │    שרת Flask (Python)        │
│   HTML / CSS         │                            │                              │
└─────────────────────┘                            │  ┌─── auth Blueprint ───────┐ │
                                                   │  │ login, register, logout  │ │
                                                   │  └──────────────────────────┘ │
                                                   │  ┌─── questionnaire BP ────┐  │
                                                   │  │ form, routine            │  │
                                                   │  └──────────────────────────┘ │
                                                   │  ┌─── community BP ────────┐  │
                                                   │  │ feed, share, react       │  │
                                                   │  └──────────────────────────┘ │
                                                   │                              │
                                                   │  services/                    │
                                                   │    routine_ai.py ───► OpenAI  │
                                                   │    audit_logger.py (Thread)   │
                                                   │                              │
                                                   │  DB: SQLite / PostgreSQL      │
                                                   └──────────────────────────────┘
```

**רכיבים:**

- **לקוח (Client):** דפדפן אינטרנט — מציג תבניות HTML/CSS שמגיעות מהשרת. כל אינטראקציה היא בקשת HTTP (GET/POST).
- **שרת (Server):** אפליקציית Flask — מטפלת בניתוב (Routing), לוגיקה עסקית, אימות משתמשים, יצירת תוכן ושמירה ב-DB.
- **מסד נתונים:** SQLAlchemy ORM מעל SQLite (פיתוח) או PostgreSQL (ייצור).
- **שירות חיצוני:** OpenAI API — נקרא מצד השרת בלבד (server-to-server).
- **Audit Logger:** Thread נפרד שכותב לקובץ — לא מעכב את תהליך הבקשה.

## תיאור האלגוריתמים המרכזיים בפרויקט {#תיאור-האלגוריתמים-המרכזיים-בפרויקט}

### אלגוריתם 1: יצירת שגרה (generate_routine)

**הדילמה:** איך ליצור שגרה חכמה אבל להבטיח שתמיד תהיה תוצאה גם אם ה-AI לא זמין?

**הפתרון:** דו-שלבי —
1. ניסיון ראשון: קריאה ל-OpenAI עם Prompt מותאם.
2. ניסיון שני (Fallback): אם נכשל — בניית שגרה מבוססת כללים.

**תיאור:**
```
function generate_routine(answers):
    if no API key or OpenAI SDK missing:
        return fallback_routine(answers)
    
    prompt = build_prompt(answers)
    try:
        response = openai.chat.completions.create(prompt)
        morning, evening = split_response(response)
        if morning and evening are valid:
            return (morning, evening, True)
        else:
            return fallback_routine(answers)
    except any error:
        return fallback_routine(answers)
```

**למה בחרנו בגישה זו:** רצינו חוויית AI עשירה אך לא רצינו שהמערכת "תיפול" אם יש בעיה ב-API. הגישה הדו-שלבית מבטיחה 100% זמינות עבור המשתמש.

### אלגוריתם 2: פיצול תשובת AI לבוקר/ערב (_split_morning_evening)

**הדילמה:** מודל השפה מחזיר טקסט אחד ארוך — איך מפצלים אותו נכון?

**הפתרון:**
1. פיצול לפי סימני `##` (כותרות Markdown).
2. זיהוי כל chunk לפי מילות מפתח ("בוקר"/"morning" → בוקר ; "ערב"/"evening"/"לילה" → ערב).
3. אם הפיצול נכשל — חצי על חצי (fallback פנימי).

### אלגוריתם 3: Audit Logger אסינכרוני

**הדילמה:** כתיבת לוגים לדיסק עלולה להאט את הבקשה. איך לתעד בלי להשפיע על ביצועים?

**הפתרון:** Producer-Consumer pattern:
- Main thread (producer): שם אירוע ב-Queue.
- Worker thread (consumer): מוציא מהתור וכותב לקובץ.
- Worker רץ כ-daemon thread — ייסגר אוטומטית כשהתהליך הראשי נגמר.

### אלגוריתם 4: Toggle תגובה בקהילה

**הדילמה:** איך לנהל like/dislike שניתן ללחוץ שוב לביטול או להחלפה?

**הפתרון:**
```
function react(share_id, user_id, value):
    existing = find_reaction(share_id, user_id)
    if not existing:
        create new reaction(value)
    elif existing.value == value:
        delete existing  // toggle off
    else:
        existing.value = value  // switch like↔dislike
```

## קטע 1: יצירת שגרה (routine_ai.py – generate_routine)

```python
def generate_routine(answers: dict[str, Any]) -> tuple[str, str, bool]:
    """מחזיר: (טקסט בוקר, טקסט ערב, האם נוצר עם OpenAI)."""
    api_key = os.environ.get("OPENAI_API_KEY", "").strip()
    if not api_key or OpenAI is None:
        return _build_fallback_routine(answers)

    client = OpenAI(api_key=api_key)
    payload = _format_answers_for_prompt(answers)
    system = (
        "אתה יועץ קוסמטולוגיה להסבר כללי בלבד. אינך מחליף רופא או רוקח. "
        "השב בעברית בלבד. פורמט ברור עם כותרות markdown קצרות, רשימות ממוספרות, "
        "ציון סוגי מוצרים (לא מותגים ספציפיים) ושלבים לבוקר ולערב בנפרד."
    )
    user_msg = f"""לפי נתוני המשתמש הבאים, בנה שגרת טיפוח מפורטת:\n\n{payload}"""

    try:
        resp = client.chat.completions.create(
            model=os.environ.get("OPENAI_MODEL", "gpt-4o-mini"),
            messages=[
                {"role": "system", "content": system},
                {"role": "user", "content": user_msg},
            ],
            temperature=0.5,
        )
        text = (resp.choices[0].message.content or "").strip()
        morning, evening = _split_morning_evening(text)
        if not morning or not evening:
            return _build_fallback_routine(answers)
        return morning, evening, True
    except Exception:
        return _build_fallback_routine(answers)
```

**הסבר:** הפונקציה מנסה ליצור שגרה עם OpenAI, ואם נכשלת מכל סיבה — חוזרת ל-Fallback. זהו הלב של המערכת.

## קטע 2: Audit Logger – Worker Thread

```python
_queue: Queue[dict[str, Any]] = Queue()

def _worker(app: Flask) -> None:
    logger = _build_logger()
    with app.app_context():
        while not _stop_event.is_set():
            try:
                payload = _queue.get(timeout=0.5)
            except Empty:
                continue
            try:
                logger.info(json.dumps(payload, ensure_ascii=False))
            except Exception:
                app.logger.exception("Failed writing audit event")

def log_audit_event(event_type: str, level: str = "info", **data: Any) -> None:
    payload = {"timestamp": _utc_now(), "event_type": event_type, "level": level, **data}
    _queue.put(payload)
```

**הסבר:** שימוש ב-Queue + Thread נפרד — כל קריאה ל-`log_audit_event` שולחת אירוע לתור ולא מחכה לכתיבה לדיסק. ה-Worker שולף ברציפות מהתור וכותב לקובץ.

def _validate_password_strength(form, field):
    value = field.data or ""
    if len(value) < 8:
        raise ValidationError("הסיסמה חייבת להכיל לפחות 8 תווים.")

## קטע 4: Markdown בטוח (XSS prevention)

```python
def render_markdown_safe(text: str | None) -> Markup:
    if not text:
        return Markup("")
    raw = markdown.markdown(text, extensions=["nl2br", "sane_lists"], output_format="html")
    clean = bleach.clean(raw, tags=_allowed_tags(), strip=True)
    return Markup(clean)
```

**הסבר:** כל תוכן Markdown (שגרה, פוסטים) עובר דרך Bleach שמסנן כל תגית HTML שלא ברשימה המותרת — כך נמנע XSS גם אם מודל ה-AI או המשתמש הכניס תגיות זדוניות.

## קטע 5: Toggle תגובה בקהילה

```python
@community_bp.route("/community/react/<share_id>/<action>", methods=["POST"])
@login_required
def react_to_share(share_id: str, action: str):
    value = 1 if action == "like" else -1 if action == "dislike" else 0
    reaction = CommunityReaction.query.filter_by(share_id=share_id, user_id=current_user.id).first()
    if reaction is None:
        reaction = CommunityReaction(share_id=share_id, user_id=current_user.id, value=value)
        db.session.add(reaction)
    elif reaction.value == value:
        db.session.delete(reaction)  # toggle off
    else:
        reaction.value = value  # switch
    db.session.commit()
```

**הסבר:** מנגנון Toggle חכם — לחיצה ראשונה יוצרת תגובה, לחיצה שנייה על אותו כפתור מבטלת, לחיצה על הכפתור הנגדי מחליפה.

## הדרכה למשתמש הרוצה לקבל שגרת טיפוח

2. **הרשמה** — לחץ על "הרשמה", הכנס אימייל, שם (אופציונלי) וסיסמה חזקה (8+ תווים, אות, מספר, תו מיוחד). לחץ "הרשמה".
3. **מילוי שאלון** — ענה על כל השאלות בכנות: סוג עור, גיל, חששות, רגישויות, מטרות, תקציב, זמן, אקלים ועוד. לחץ "שליחה ויצירת שגרה מותאמת".
4. **צפייה בשגרה** — תראה שגרת בוקר וערב מותאמת. ניתן לחזור לשאלון ולעדכן בכל עת.
5. **שיתוף בקהילה** — אם רוצים — גלול לדף "קהילה", מלא שם תצוגה ולחץ "פרסמי".

## הדרכה למנהל המערכת (מפעיל)

1. **התקנה מקומית:**
   ```
   cd personal_skin
   py -3 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   py -3 -m pip install -r requirements.txt
   ```
2. **הגדרת .env:** העתק `.env.example` ל-`.env`, הגדר `FLASK_SECRET_KEY` ו-`OPENAI_API_KEY` (אופציונלי).
3. **הפעלה:** `py -3 run.py` — השרת עולה ב-`http://127.0.0.1:5000`.
4. **עצירה:** Ctrl+C.
5. **פריסה לייצור:** דחוף ל-GitHub, חבר ל-Render (Blueprint), הגדר משתני סביבה.
